The exact source revisions reviewed were duck-sqllsp `76a1a75dbb602820e89e339a7617049ea234bb0d` and sqlsift `76c20722a7cb617b67a2b63d4a2483e906e30749`. Their current repositories can change. SQLFluff's [reference rules](https://docs.sqlfluff.com/en/stable/reference/rules/references.html) were also read. The duck-sqllsp rule named `for_update_of_unknown` concerns PostgreSQL SELECT row locks, not SQLite CREATE TRIGGER event names.

Fixture SQL is generated by `examples/make_demo.py`; `schema.sql` contains its CREATE TABLE and CREATE TRIGGER statements, and `triggers.sql` contains the three trigger statements. The reference script is intentionally limited to this unquoted, uncommented fixture. It is not used by the checker. The focused tool adds source positions, repeated occurrences, mixed-list preservation, honest omissions, and guarded snapshot reads to the same basic metadata comparison.

SQLite's [CREATE TRIGGER documentation](https://www.sqlite.org/lang_createtrigger.html#description) explicitly describes unknown UPDATE OF names being silently ignored. Its [rowid documentation](https://www.sqlite.org/rowidtable.html) describes implicit aliases and their shadowing by declared columns. Both were opened on 2026-10-31; neither page provides a publication date for the cited rule. This engine behavior is the product's concrete basis. General attention to assistant coding mistakes is not evidence of demand for this checker.
